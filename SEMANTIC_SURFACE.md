# Crucible — Semantic Surface

**Status:** provisional present-tense authority

This file stays small. Crucible should earn vocabulary through executable pressure rather than receive an ontology in advance.

## Purpose

Crucible is a world we can inhabit and grow conversationally. A described phenomenon should be realizable as the smallest coherent semantic machinery, experienced as executable evidence, refined when necessary, and then allowed to compose with what already exists.

## Current commitments

### Tiny verbs, large causal wakes

Prefer small underlying laws whose consequences cross systems. Do not script interaction richness separately when shared physical or semantic rules can produce it.

### Construction pressure earns vocabulary

Do not prebuild a generic editor, force framework, ownership hierarchy, scheduler graph, archetype system, or universal payload vocabulary. Add machinery when a concrete attempted construction needs it.

### The ECS kernel stays boring

ECS is useful as a tiny model-facing semantic substrate. Not everything must be an entity. Dense subordinate populations may remain system-owned state when that is the clearer realization.

### Systems produce world state; the frame owns presentation

Behavioral systems mutate semantic state. Presentation synchronizes afterward. The recurring frame owns rendering.

### Physical consequence before decorative behavior

Where practical, gravity, support, collision, geometry, material state, and other shared laws should explain behavior across multiple things.

### Source, executable, conversation, and Git have different jobs

Conversation is the ordinary human construction surface. Modular source is the model-facing implementation surface. Candidate executables are experienced evidence. Git is durable source and provenance.

## Current world

T0 is deliberately only a construction bench: a contained warm geological locus, a tiny ECS, a frame-owned Three.js runtime, camera inspection, visible diagnostics, and a small loose-matter gravity probe.

The loose matter is evidence that a semantic actor can participate in a shared world law. It is not a commitment that bearings, granular matter, terrain editing, or any particular payload belongs in Crucible.

## Visual direction

Warm organic and geological materials; cinnamon, cinnabar, brass, timber, rust, stone, verdigris, and restrained mineral/poison accents. Chunky readable silhouettes. Machinery should become understandable through form and motion.

Octonut + dome is a useful recurring instinct for discrete loci, not yet a universal style law.

## Non-commitments

Crucible does not yet commit to deformable terrain, payload catalogs, logistics, combat, a generic physics engine, runtime model inference, a backend, or Foundry's implementation architecture.

## Present finish line

The bench is ready when we can experience the world and immediately say “put X in there,” then implement X without first extending a framework.
